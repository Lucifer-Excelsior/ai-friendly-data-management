## 建议的引用信息

请尽量记录以下信息：项目名称、具体章节或条目、页面已有作者/贡献者署名、版本或提交标识、访问日期和链接。不要把整个项目的维护者自动当成每段内容的唯一作者。

引用格式示例：

> 《AI友好的数据管理》项目，〈具体章节标题〉，章节所列作者或贡献者，版本或提交标识，访问日期，具体页面链接。

这是便于追溯的建议格式。依法需要的署名和其他义务仍应遵守；不同论文或出版机构的格式要求，可据实调整。提供了引文和来源，不等于获得了超出法定例外的复制或改编许可。

## 关于论文、出版与专利

### 论文与图书

本项目保留对其受保护表达进行复制、改编、翻译和汇编等使用的授权权利。禁止未经许可搬运或改写书稿并冒认原创，与禁止他人开展相同方向的研究，是两回事。依法适当引用和不侵权的独立成果，不因本许可而被一概禁止。

需要授权时，请指出具体使用的段落、图表、案例或模板，以及准备如何使用。维护者会协助识别对应权利人；维护者不能仅凭仓库管理权限代替所有贡献者授予商业或出版许可。

### 专利

本许可不授予专利许可，也不会使书稿作者自动取得专利权。公开且充分披露的技术可能构成后续专利申请的现有技术，但是否满足相关条件需要具体判断。本项目不保证审查机构会自动发现仓库，也不保证阻止任何人提交申请。

有价值的公开记录包括完整技术描述、公开版本、Release、原稿与传播证据。Git 提交时间不应单独被当作无争议的首次公开证明。公开披露也可能影响作者或贡献者自身未来申请专利的机会；普通自行上传 GitHub 不能当然视为享有不丧失新颖性的宽限期。

## 如何申请额外授权

使用已启用的 GitHub Discussion，或创建 Issue，并只提供可公开的信息：

1. 想使用的章节、页面或图表及其版本。
2. 拟进行的复制、改编、出版、教学或其他使用。
3. 是否收费、投放广告、接受商业赞助，或纳入有偿交付。
4. 大致传播范围、媒介和预计时间。
5. 希望如何署名和注明来源。

**Discussion 和 Issue 都可能被公众看到。请勿发布姓名、电话、邮箱、合同、未公开论文、专利申请材料、客户数据或商业秘密。** 如需进一步处理非公开信息，由维护者后续说明适当渠道。申请本身、点赞、沉默或一般性讨论均不表示授权完成。
